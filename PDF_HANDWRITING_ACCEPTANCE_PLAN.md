# План Валидации PDF-Конспектов (Рукописный Режим)

Updated: 2026-03-05
Project root: `C:\plotter_pdf`

## 1. Цель

Довести режим рукописного вывода PDF до стабильного продакшен-уровня для конспектов:

1. корректное распознавание текста, формул, графиков;
2. отсутствие двойных штрихов в буквах и знаках;
3. управляемая многостраничная печать с обязательной паузой на смену листа;
4. повторяемый протокол проверки: сначала 1 эталонный лист, потом 5 разных листов.

## 2. Обязательные входные данные

Нужен один реальный PDF русскоязычной научной статьи (обязательно формулы + графики), из него:

1. `Page A` — эталонная страница для доводки до совпадения;
2. `Page B..F` — еще 5 страниц для проверки переносимости настроек.

Рекомендуемый набор страниц:

1. страница с плотным основным текстом;
2. страница с inline-формулами;
3. страница с display-формулами;
4. страница с графиком/диаграммой;
5. страница со смешанной версткой (подписи + рисунок);
6. страница с таблицей или сложными индексами.

## 3. Готовность среды (перед тестами)

Проверить:

1. `Inkscape` и `pdftocairo` доступны;
2. `tools/autotrace/autotrace.exe` доступен;
3. плоттер подключается стабильно;
4. профиль области листа настроен (`A4/A3/custom`);
5. в UI включен рукописный режим (`handwriting`).

Быстрые команды:

```powershell
.\.venv\Scripts\ruff.exe check src plotter_studio tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.\.venv\Scripts\python.exe -m pytest -q
```

## 4. Протокол “1 страница до идеала”

### Шаг 1. Выбор базовой страницы

1. Включить `handwriting`.
2. Выбрать `Page A` (сложная смешанная страница).
3. Запустить preview и dry-run draw.

### Шаг 2. Метрики качества

Для `Page A` фиксировать:

1. читабельность текста (субъективная оценка 1..5);
2. корректность формул:
   - индексы/степени;
   - знаки `= + - / *`;
   - скобки и дроби;
3. корректность графиков:
   - оси, деления, подписи;
   - отсутствие пропусков линий;
4. отсутствие двойных штрихов:
   - не должно быть “дублированных” обводок букв;
5. отсутствие вылета за границы листа.

### Шаг 3. Итеративная доводка

После каждого прогона менять только 1–2 параметра и повторять:

1. параметры качества/сглаживания;
2. режимы контуров изображений;
3. шрифт handwriting и формульный шрифт.

Критерий выхода из этапа:

1. `Page A` проходит все метрики без критичных дефектов в 3 подряд прогонах.

## 5. Протокол “+5 страниц на переносимость”

Для `Page B..F`:

1. те же настройки, что дали лучший результат на `Page A`;
2. по каждой странице:
   - preview;
   - dry-run;
   - реальный draw;
3. фиксировать те же метрики.

Критерий приемки блока:

1. минимум 5 из 5 страниц без критичных дефектов;
2. не более 1 мелкого дефекта на страницу (например, редкий шум контура без потери смысла).

## 6. Многостраничный draw и смена листа

Требование:

1. в режиме `all pages` между страницами должна быть пауза с подтверждением смены листа;
2. пользователь либо продолжает печать, либо отменяет операцию;
3. отмена на паузе не должна приводить к крашу/зависанию.

Проверка:

1. прогон 3+ страниц;
2. подтверждение на 1-й и 2-й паузе;
3. отдельный прогон с отменой на 1-й паузе.

## 7. Тесты, которые должны быть в кодовой базе

### Unit/Integration (автоматические)

1. метод3 page-mode, `source_all_pages=True`;
2. паузы между страницами (continue/cancel);
3. генерация preview/G-code для каждой страницы;
4. preflight-проверки границ;
5. проверка отсутствия регрессий по существующему пайплайну.

### Manual acceptance (обязательные)

1. `Page A` доведен до эталона;
2. `Page B..F` подтверждают переносимость;
3. лог результатов сохранен в отдельный отчет.

## 8. Лог валидации (формат)

Для каждой страницы:

1. source file + page number;
2. профиль настроек;
3. оценка текста/формул/графиков;
4. замечания по двойным линиям;
5. итог: `pass/fail`;
6. приложенные артефакты (`_tmp/latest_*.svg/.pdf/.nc`, фото листа после рисования).

## 9. Критерии “готово к использованию без нареканий”

Считаем готовым только если:

1. все автотесты зеленые (`ruff + unittest + pytest`);
2. `Page A` стабильна (3/3 прогона без критики);
3. `Page B..F` проходят приемку;
4. многостраничный режим подтвержден с паузами смены листа;
5. нет критичных двойных штрихов на буквенных контурах.

## 10. Автоматизированный прогон (реализовано)

Добавлен скрипт:

`scripts/run_pdf_handwriting_acceptance.py`

Назначение:

1. прогоняет выбранные страницы PDF в режиме `handwriting` через реальный preview-пайплайн;
2. сохраняет по каждой странице `SVG/PDF/NC` в отдельные файлы;
3. считает G-code метрики:
   - число сегментов,
   - длину траектории,
   - прокси-метрику “двойных линий” (`segments_duplicate_ratio`);
   - долю микросегментов (`segments_tiny_ratio`, длина < `0.12 мм`);
4. формирует JSON-отчет.
5. при передаче `--baseline-report` добавляет comparison-блок с дельтами метрик по страницам.

Quality-gates (по умолчанию):

1. `segments_duplicate_ratio <= 0.002`
2. `segments_tiny_ratio <= 0.015`

Если gate не пройден, страница помечается как `ok=false` в отчете.

Запуск:

```powershell
.\.venv\Scripts\python.exe scripts\run_pdf_handwriting_acceptance.py `
  --pdf data\acceptance\r232a.pdf `
  --pages 1,2,3,4,5,6 `
  --out-dir _tmp\acceptance\r232a `
  --quality high `
  --contours always `
  --max-duplicate-ratio 0.002 `
  --max-tiny-ratio 0.015
```

Пример сравнения с предыдущим прогоном:

```powershell
.\.venv\Scripts\python.exe scripts\run_pdf_handwriting_acceptance.py `
  --pdf data\acceptance\r232a.pdf `
  --pages 1,2,3,4,5,6 `
  --out-dir _tmp\acceptance\r232a_new `
  --baseline-report _tmp\acceptance\r232a\handwriting_acceptance_report.json
```
